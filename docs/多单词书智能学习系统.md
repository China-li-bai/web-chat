# 多单词书智能学习系统（全局今日计划 + 配额分配 + 当日学习聚合）

以下是基于现有代码的深入分析与可执行建议，兼顾 INTJ 的抽象-系统视角、乔布斯式“从体验倒推技术”、以及逆向批判性思维。重点围绕：多词书、大量单词、分批学习、数据一致性、跨端自适应布局与最小可执行原则。

一、现有实现梳理（数据流与UI/UX现状）

数据模型与流转
words：包含词条、type等；与 wordbooks（可选）关联。
learning_progress：核心学习状态表，字段涵盖 nextReview、state(new/learning/review/relearning)、stability/difficulty/retrievability、reviewCount/lapseCount、userId 等。所有 FSRS 决策都以该表为唯一事实源（Single Source of Truth）。
study_logs：记录每次学习响应（again/hard/good/easy）及前后记忆参数；用于统计与算法回溯。
统计：statsService 提供 mastered、正确率等聚合，word_type_statistics 做类型维度分析。
算法与会话
MemoryLearningManager：集成 spacedRepetition（FSRS 参数化）、difficultyAdaptive（难度自适应）、activeRetrieval（交错与认知负荷控制）。createLearningSessionForWordbook 从 DB 拉取到期项并映射为 LearningItem，再由管理器生成会话。
processStudyResponse：将用户反馈写回 learning_progress 与 study_logs，并更新统计；利用 FSRS 返回 nextReview。
页面与交互
LanguageLearning
WordbookSelectionPage：展示词书卡片及进度，单词书级别“开始学习”进入会话。
LearningSessionPage：基于某词书的待学队列，展示进度条、统计、响应按钮；支持自动为“弱项”生成下一次复习列表与 schedulePlannedReviews。
StatisticsPage：总体统计可视化。
ReviewPlanner
review-planner-page：按词书汇总 dueCount、upcomingCount、totalPlanned；可切换词书查看到期项并启动学习。
已有能力与缺口
已具备：FSRS驱动的 nextReview、按词书创建会话、到期队列分组与预览、学习响应写回、基础统计。
缺口：跨词书“全局今日计划”与“每日学习量配额”机制；多词书配额分配与交错；移动端优先的快速入口；一致的每日计划与会话切片的统一数据契约。
二、需求挑战与约束（逆向批判）

挑战
大量单词（100~3000）：必须进行“今日可执行队列”切片，且保证切片可解释性与稳定性（同一日不随刷新无规则波动）。
多词书：不同词书到期量差异大，需公平与效率兼顾的配额分配（避免某词书长期积压）。
跨端布局：移动端需更简洁的操作入口与滚动流式展示；Web端需要数据密度更高的总览与筛选。
约束
数据统一性：任何“今日计划”必须以 learning_progress.nextReview + userId 为计算源；不要引入二次缓存破坏一致性。
最小可执行：先“计划数据层”与“一个总览入口”，再逐步增加高级策略。
稳态反馈：UI刷新应区分“计划生成（一次性）”与“执行进度（动态）”，避免用户感知混乱。
三、设计建议（信息架构、策略与UI/UX）

信息架构
全局“今日计划”实体：TodayPlan
生成时间戳 generatedAt
配额 dailyQuota（总数）与分配 perWordbookQuota: Map<wordbookId, count>
切片明细 items: Array<{ wordId, wordbookId, nextReview, retrievability, state }>
来源：getReviewQueueGroupedByWordbook + 配额算法
会话与计划关系
会话从 TodayPlan.items 派生，遵循目标时长/认知负荷，允许多次会话消耗今日队列。
分批学习策略（可执行且可解释）
步骤
统计每个词书的到期数 D_i（可选含24h内 upcoming）
总到期 D_total = Σ D_i
配额总数 Q_total = 用户每日学习量（例如 60）
初始分配 q_i = round(Q_total * D_i / D_total)，确保 Σ q_i = Q_total，通过微调消除取整误差
最小保障：若某词书 D_i > 0 且 q_i = 0，分配至少 1，随后在其他词书上减去 1（公平性）
切片选择：按 retrievability 从低到高选择 q_i 个，保证效率优先与可解释性
交错类型：在会话层按 activeRetrieval 的 interleaveTypes 实现类型交错，不改变 per-wordbook 切片结果
稳定性
生成计划当日固定（写入 TodayPlan 存储或缓存），重复进入不会变化；只有用户明确“重生成”才改变。
UI/UX（Web + 移动端响应式）
全局仪表盘（顶层页面）
上方：总进度环形图（完成比例）、今日配额进度条（已完成/总配额）、正确率

## 1. 信息架构与数据契约

### 1.1 实体与表
- words(id, word, type, wordbookId, userId, ...)：词条信息
- wordbooks(id, name, userId, ...)：词书信息（可选）
- learning_progress(id, wordId, userId, nextReview, state, stability, difficulty, retrievability, reviewCount, lapseCount, lastReview)：学习状态，SOT
- study_logs(id, userId, itemId, timestamp, response, responseTime, confidence, previousStability, previousRetrievability, newStability, newRetrievability)：学习响应日志
- word_type_statistics(userId, date, wordType, totalReviews, correctReviews, avgStability, avgRetrievability, lastUpdated)：类型维度统计（已存在）
- 今日计划（内存/持久化结构）：TodayPlan（详见类型）

### 1.2 类型定义（供前后端与 LLM 执行共享）
```
export type TodayPlan = {
  generatedAt: string; // ISO 时间
  dailyQuota: number;  // 当日总配额
  perWordbookQuota: Array<{
    wordbookId: number;
    wordbookName?: string;
    quota: number;         // 分配数 q_i
    dueCount: number;      // 该词书到期数
    upcomingCount: number; // 24h 内即将到期数（可选）
  }>;
  items: Array<{
    id: string; // wordId 字符串
    wordId: number;
    wordbookId: number;
    word: string;
    nextReview: string; // ISO
    retrievability?: number;
    state: 'new'|'learning'|'review'|'relearning';
  }>;
};
```

## 2. 服务接口与算法

### 2.1 依赖接口（已部分存在）
- getReviewQueueGroupedByWordbook(params: { userId: string; includeUpcoming?: boolean }): Promise<Array<{ wordbookId: number; wordbookName?: string; dueCount: number; upcomingCount: number; totalPlanned: number }>>
- getDueItemsByWordbook(params: { userId: string; wordbookId: number; includeUpcoming?: boolean; page?: number; pageSize?: number; letter?: string }): Promise<{ items: Array<{ id: string; word: string; nextReview: string; retrievability?: number }>; total: number }>
- createLearningSessionForWordbook(wordbookId: number, userId: string): Promise<LearningSession>（现有）
- processStudyResponse(session, itemId, response, responseTime, userId): Promise<...>（现有）

### 2.2 新增接口
- getTodayPlan(params: { userId: string; dailyQuota: number; includeUpcoming?: boolean }): Promise<TodayPlan>
  - 步骤：
    1) groups = getReviewQueueGroupedByWordbook({ userId, includeUpcoming })
    2) D_i = groups[i].dueCount（可选将 upcomingCount 纳入权重）
    3) D_total = Σ D_i；Q_total = dailyQuota
    4) 初始分配 q_i = round(Q_total * D_i / D_total)
    5) 最小保障：若 D_i>0 且 q_i=0，则设 q_i=1，并在其它 q_j>1 的词书减去 1，直至 Σ q_i = Q_total
    6) 对每个词书，按 retrievability 从低到高获取 q_i 个到期项：getDueItemsByWordbook + 排序选取
    7) 生成 TodayPlan，写入内存或本地存储持久化，保证同日稳定；仅“重生成”才更新
- startSessionFromTodayPlan(params: { plan: TodayPlan; targetDuration?: number }): Promise<LearningSession>
  - 从 plan.items 生成跨词书 LearningItem 列表，交由 MemoryLearningManager 进行 activeRetrieval 的类型交错与时长控制
- aggregateDailyStudyAndUpdateProgress(params: { userId: string; date?: string }): Promise<{ updatedWordbooks: Array<{ wordbookId: number; masteredCount: number; progress: number }> }>
  - 目标：将当日 study_logs 聚合为“已复习词汇集合”，更新词书进度
  - 步骤：
    1) 读取当日 study_logs where userId = ? and date = today（按本地时区或统一 UTC+8，推荐统一 ISO + 前端显示本地）
    2) 汇总 itemId（wordId）唯一集，统计该词书下已复习数量增量
    3) 读取词书级总词数：SELECT COUNT(*) FROM learning_progress where userId=? and wordId in (words by wordbookId)
    4) 读取已掌握数（示例定义：state='review' 且 retrievability≥阈值，如 0.85）：SELECT COUNT(*) ...
    5) 计算 progress = masteredCount / wordCount * 100
    6) 将统计写回 wordbookService 的返回或单独统计表（如 learning_statistics/wordbook_daily），用于 UI 显示与卡片徽标更新
  - 注：不改变 learning_progress 的掌握判定逻辑，仅做聚合与统计更新；掌握状态仍由 processStudyResponse + FSRS 决策。

### 2.3 数据一致性与时间边界
- 统一使用 ISO 字符串存储 nextReview/lastReview；聚合按 [当天 00:00, 23:59:59) 时间窗
- 若存在跨时区用户，前端传入 date（YYYY-MM-DD）并转换为本地时间窗；服务端以传入窗计算
